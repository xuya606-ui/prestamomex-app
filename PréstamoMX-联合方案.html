📋 一页摘要

核心结论

两个项目不是并列关系，而是「渠道 × 内容」的乘积关系。项目 1 是「管道」，项目 2 是「管道里流的内容」。任何一者单独做都不可能成，必须同步落地。

  • 没有项目 1 的触达体系，项目 2 的券推不出去（频次/静默/合规没人管）
  • 没有项目 2 的券内容，项目 1 的触达形式空转（触达不等于转化）
  • 必须共建 4 个底座：触达中台、营销偏好中心、合规规则中心、A/B 平台

🔗 关联分析（两个项目的协同设计）

0 · 一页结论

为什么必须联动？

两个项目分别解决了同一个问题的两面：

  • 项目 1（信息触达）：解决"怎么把信息送到用户眼前"——定义通道、时机、频次、合规
  • 项目 2（优惠券）：解决"送什么内容能让用户动起来"——定义内容、激励、闭环

两者不是并列，而是 「管道 × 内容」 的乘积关系。单做任一项，转化率都上不去。

1.2 需求分析与痛点

7 大痛点

  1. 触达形式单一：过度依赖 Push，其他形式覆盖不足
  2. 触达结点不全：复借/召回/提额 等高价值结点缺失
  3. 频次失控：用户被反复打扰，关闭通知率 25%
  4. 转化率低：Push 打开率仅 8-12%，业务转化弱
  5. 合规风险：营销文案无 opt-in、催收时段违规
  6. 数据孤岛：触达数据与业务数据未打通
  7. 节日运营弱：Buen Fin / 亡灵节 / 圣诞 等节日无专项触达

🎟️ 项目 2：优惠券使用率提升

2.1 业务背景

行业现状

  • 市场：墨西哥现金贷市场竞争白热化，营销费用高
  • 券玩法：cashback / 折扣 / 提额 / 邀请奖励 / 体验金 / 免息
  • 行业基准：业内优惠券核销率 8%-25%，本项目目标从 15% → 30%
  • 竞品：Kueski Pay / Stori Cashback / NuPay Promo / Albo Promos / Mercado Pago Cupones

2.2 需求分析与痛点

5 环节漏斗 + 7 用户故事

曝光(100%) → 点击(50%) → 领取(30%) → 使用(15%) → 完成(12%) ↓ ↓ ↓ ← ← 核心流失区 -50% -40% -50%

核心结论：「领取→使用」是绝对死亡漏斗，流失 50%。这是 5 大策略要解决的核心命题。

7 个用户痛点场景

  1. María 32 岁销售：都忘了有这张券 → 提醒时机错位
  2. Carlos 28 岁快递员：想用但找不到入口 → 入口迷失
  3. Lucía 41 岁老师：规则太复杂，怕被坑 → 规则不透明
  4. Roberto 35 岁小企业主：不需要提额券 → 用户分层粗糙
  5. Fernanda 25 岁大学生：push 排第 5 谁看 → 触达被噪音淹没
  6. Diego 30 岁工程师：邀请奖励 30 天没到 → 文案承诺与实际不一致
  7. Valeria 38 岁家庭主妇：卸载了，短信像诈骗 → 召回通道错

2.3 5+2 策略 v1.1 +1.5/1.6 + v1.2 增量

🎁 v1.2 新增 · 首借红包包装（会议重点决策）

把"首借用户"账户内的所有优惠券统一包装为「首借红包」(Bonificación Primer Préstamo)，在券中心/触达文案/弹窗中统一标识。

  • 强化"专属"心智，避免用户觉得是通用福利
  • 端内只做"包装"，不调整后端发券规则（龙哥团队职责）
  • 影响：券中心 banner / 申请页"首借红包可省 $X" / 退出挽留弹窗 / 未出额首页
策略目标漏斗环节核心解法预期提升
1 场景化推荐（v1.1 调整） 领取→使用 券不"找用户"，而是"在能用的地方出现"：申请页不自动选中，用虚线 banner 提示+手动选；还款页手动 toggle；邀请页浮动按钮 50% → 65%
1.5 手动引导设计原则（v1.1 新增） 决策权 申请页"继续"按钮 = Continuar sin cupón（不强调使用）；Elegir otro cupón 文本入口；尊重 CONDUSEF 抗诱导合规 —
1.6 临期/非临期分区（v1.1 新增） 临期券核销 券中心分两区：🔥 即将到期（≤7天，红色虚线+角标）置顶 / 📋 常规券（>7天）置底；点击临期区进入 P8 过期提醒 临期核销 35% → 55%
2 智能时机 曝光→点击 + 领取→使用 用户行为驱动的实时触发：还款日 D-3 提醒、券过期前 24h 提醒、放款后立即推提额券 Push 点击 8% → 18%
3 规则透明化 点击→领取 收益前置、限制后置、实时计算器、历史案例展示、T&C 一键展开 60% → 75%
4 用户分层 整套链路 5 类用户 × 各自专属券池：新/首借/复借/高净值/流失 人均券价值 +35%
5 社交化裂变 获客 + 召回 即时履约 + 阶梯奖励 + 进度可视化：1/3/5/10 阶梯、双向券、防刷 邀请贡献 9% → 18%
6 流失召回（锦上添花） 流失用户 按流失时长切换通道：30d→APP+Push，60d→+WhatsApp，90d→+邮件，180d+→不发券 召回率 ≥ 15%

2.7 7 条合规铁律

  1. 避免诱导多头借贷：邀请上限 5 人/月；不得用"借更多"作为券收益
  2. 规则透明：任何券必须同屏挂 T&C（PROFECO 罚款 50-300 万 MXN）
  3. CAT 透明：提额券必须挂 CAT 计算器
  4. 可关闭：设置 → 营销偏好 → 关闭 push（LFPDPPP）
  5. 不绝对化：不得用 "100% garantizado / sin riesgo / dinero fácil"
  6. 未成年人保护：任何券必须 18+ 才可领取
  7. 逾期合规：罚息减免券不得在逾期 D+3 后推送（SMS 催收合规）

⏪ 如何回溯到任意旧版本

Git 的好处是 所有历史 commit 永久保留，可以 1 条命令回到任意历史状态。

方法 1 · Git 命令（推荐 · 程序员）

# 1. 查看所有历史 commit
git log --oneline

# 2. 回到指定版本（创建新分支保留当前进度）
git checkout -b restore-v1.0 bbf952a
# 此时工作区就是 v1.0 的状态

# 3. 回到最新版
git checkout main
git pull

方法 2 · GitHub ZIP 下载（推荐 · 任何人）

任意 commit 都可以下载为 zip 包：

# v1.1 当前版
https://github.com/xuya606-ui/prestamomex-app/archive/c324c7c.zip

# v1.0 首发版
https://github.com/xuya606-ui/prestamomex-app/archive/bbf952a.zip

# 最新 main 分支
https://github.com/xuya606-ui/prestamomex-app/archive/refs/heads/main.zip

# 任意 commit: 把 commit hash 替换进去即可
# 格式：https://github.com/<user>/<repo>/archive/<hash>.zip

方法 3 · GitHub 网页浏览器查看

在 commits 页面 点击任意 commit，可以：

  • 📋 Browse files：查看该版本的文件树
  • 🔍 View commit details：查看 diff（行级别改动）
  • ⬇ Download ZIP：下载该版本完整包
  • 🔀 Compare：对比任意两个 commit 的差异

方法 4 · 单个文件历史

想看某个文件（比如 info/04-产品规划与设计思路.md）的历史？

https://github.com/xuya606-ui/prestamomex-app/commits/main/info/04-产品规划与设计思路.md

点开可看每个 commit 对该文件的修改。

方法 5 · 创建 Release Tag（建议）

如果想要更清晰的"版本号"管理，可以在 GitHub 上给重要 commit 打 tag：

git tag v1.1 c324c7c
git tag v1.0 bbf952a
git push origin --tags

打 tag 后，下载链接可以更简洁：https://github.com/xuya606-ui/prestamomex-app/archive/refs/tags/v1.1.zip
